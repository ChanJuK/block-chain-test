# 블록체인 왕초보 실습 코스

이 프로젝트는 **블록체인을 직접 작게 구현하면서** 배우는 8주 입문 과정입니다. 복잡한 프레임워크나 코인 투자 이야기는 뒤로 미루고, "데이터가 왜 믿을 수 있게 되는가"부터 차례로 확인합니다.

## 준비물과 약속

- 언어: JavaScript (Node.js)
- 테스트: Node.js 기본 테스트 도구 (`node --test`)
- 매 단계: 개념을 짧게 읽고 → 코드를 직접 작성하고 → 테스트로 확인합니다.
- 이해가 안 되는 부분은 암기하지 않습니다. 코드와 테스트 결과를 보고 질문하며 넘어갑니다.

## 전체 커리큘럼

| 단계 | 주제 | 직접 만들 결과물 | 핵심 질문 |
| --- | --- | --- | --- |

> 1~5단계를 끝내면 의존성 없는 미니 블록체인이 완성됩니다. 6~8단계는 그 기반 위에서 실제 블록체인 개발 도구로 확장합니다.

## 권장 페이스

- 주 3회, 회당 45~60분
- 한 단계는 보통 1~2회에 마칩니다. 막히면 다음 단계로 넘어가지 않고 테스트를 통과시키는 데 집중합니다.
- 예상: 6~8주. 빠르게 끝내는 것보다 각 테스트를 자기 말로 설명하는 것이 목표입니다.

## 매 단계의 진행 방식

1. README의 해당 단원 개념을 10분 이내로 읽습니다.
2. `src/`의 코드에서 빈 부분 또는 새 기능을 직접 구현합니다.
3. `npm test`를 실행합니다.
4. 테스트가 모두 통과하면 "입력 / 처리 / 결과"를 한 문장으로 설명합니다.
5. 작은 변형 하나를 시도합니다. 예: 글자 하나를 바꿔 해시가 달라지는지 확인합니다.

## 지금: 1단계 — 해시 함수

### 배울 개념

- **해시**는 어떤 길이의 데이터를 고정된 길이의 문자열로 바꾸는 계산입니다.
- SHA-256은 같은 입력에 항상 같은 결과를 냅니다.
- 입력이 아주 조금만 달라져도 결과는 크게 달라집니다.
- 해시는 암호화와 다릅니다. 원래 입력을 되돌려 얻는 용도가 아닙니다.

### 실습 목표

`src/01-hash.js`의 `calculateHash`가 문자열을 받아 SHA-256 16진수 해시를 돌려주게 만듭니다. 현재는 완성된 예시가 들어 있으므로, 먼저 테스트를 실행하고 결과를 읽어 보세요.

```bash
npm test
```

### 확인 과제

1. `"hello"`를 `"Hello"`로 바꿔 두 결과가 얼마나 다른지 확인합니다.
2. 같은 값을 두 번 넣으면 결과가 같은지 확인합니다.
3. 테스트 하나를 추가해 `"blockchain"`의 해시를 검증합니다.

### 블록이 해시로 연결되는 모습 보기

아래 명령을 실행하면 블록 3개가 표로 출력됩니다.

```bash
npm run example:chain
```

출력에서 `2번 블록의 previousHash`가 `1번 블록의 hash`와 같은지, `3번 블록도 2번 블록의 hash`를 기억하는지 확인하세요.

`src/01-chain-example.js`의 첫 번째 거래에서 `1 코인`을 `100 코인`으로 바꾼 뒤 다시 실행해 보세요. 첫 번째 블록의 `hash`가 달라지고, 따라서 다음 블록이 기억하던 이전 해시와 연결되지 않는 상황을 다음 단계에서 검증하게 됩니다.

이 예제에는 `isValidChain()`도 들어 있습니다. 1번 블록의 거래를 `100 코인`으로 바꾸고 해시까지 다시 계산해도, 2번 블록은 **변경 전** 해시를 기억하고 있어 `valid: false`가 출력됩니다.

### 다음 단계로 갈 기준

- `npm test`가 통과한다.
- 해시가 왜 블록 데이터 변조 탐지에 도움이 되는지 자기 말로 설명할 수 있다.
- `src/02-block.js`를 만들 준비가 되었다.

| 해시 | 데이터의 디지털 지문 |

| 지갑 | 코인 자체가 아니라, 서명에 필요한 키를 관리하는 도구 |

## 지금: 2단계 — 블록 하나 만들기

### 배울 개념

블록은 단순한 거래 문장 하나가 아니라, 다음 정보를 하나로 묶은 기록 상자입니다.

| 속성 | 역할 |
| --- | --- |
| `number` | 블록의 순서 |
| `timestamp` | 블록을 만든 시간 |
| `data` | 기록할 거래 내용 |
| `previousHash` | 바로 앞 블록의 해시. 첫 블록은 `0`으로 시작 |
| `hash` | 위 정보를 모두 합쳐 만든 현재 블록의 디지털 지문 |

### 실습 순서

1. `src/02-block.js`를 엽니다.
2. `constructor`가 블록의 정보를 `this.속성명`에 저장하는 모습을 읽습니다.
3. `calculateHash()`가 왜 `number`, `timestamp`, `data`, `previousHash`를 모두 해시에 포함하는지 생각해 봅니다.
4. 아래 명령으로 테스트를 실행합니다.

```bash
npm test
```

### 직접 바꿔 보기

`test/02-block.test.js`에서 다음 중 하나를 바꾸고 테스트 결과를 확인하세요.

- 거래 내용을 `1 코인`에서 `2 코인`으로 변경하기
- 시간을 다른 값으로 변경하기
- `previousHash`를 다른 문자열로 변경하기

어느 하나만 바꿔도 블록의 `hash`는 달라집니다. 그래야 거래 내용뿐 아니라 **블록의 순서와 연결 정보**까지 보호할 수 있습니다.

## 지금: 3단계 — 블록을 체인으로 연결하기

### 배울 개념

`Blockchain`은 여러 `Block`을 순서대로 보관하는 객체입니다. 새 블록을 만들 때는 사람이 이전 해시를 직접 적지 않습니다. `getLatestBlock()`으로 마지막 블록을 찾고, 그 블록의 `hash`를 새 블록의 `previousHash`에 자동으로 넣습니다.

```text
제네시스 블록(hash A)
        ↓
1번 거래 블록(previousHash: A, hash B)
        ↓
2번 거래 블록(previousHash: B, hash C)
```

### 실습 순서

1. `src/03-blockchain.js`를 엽니다.
2. `constructor()`가 제네시스 블록 하나로 배열을 시작하는 모습을 봅니다.
3. `addBlock()` 안에서 `previousBlock.hash`가 `previousHash`로 전달되는 줄을 찾습니다.
4. 아래 명령으로 세 블록의 연결을 표로 봅니다.

```bash
npm run example:blockchain
```

### 직접 바꿔 보기

`src/03-blockchain.js`의 실행 예제에 거래 하나를 더 추가해 보세요.

```js
blockchain.addBlock('서연이 민지에게 0.2 코인을 보냄', '2026-11-02T10:02:00.000Z');
```

새 행의 `previousHash`가 바로 위 행의 `hash`와 같은지 확인하세요.

## 지금: 4단계 — 무결성 검증하기

### 배울 개념

`isValid()`은 체인을 처음부터 끝까지 살펴보며 두 가지를 검사합니다.

1. **블록 내부 검사:** 현재 데이터로 다시 계산한 해시가, 블록에 저장된 `hash`와 같은가?
2. **블록 연결 검사:** 현재 블록의 `previousHash`가 실제 이전 블록의 `hash`와 같은가?

둘 중 하나라도 다르면 `false`를 돌려줍니다.

### 실습 순서

1. `src/03-blockchain.js`의 `isValid()`을 읽습니다.
2. 아래 명령을 실행합니다.

```bash
npm run example:integrity
```

3. 세 줄의 결과를 확인합니다.

```text
정상 체인: true
데이터만 변조: false
데이터와 1번 블록 해시를 함께 변조: false
```

마지막 줄이 중요합니다. 변조한 사람이 1번 블록의 해시까지 새로 만들어도, 2번 블록은 예전 해시를 `previousHash`로 기억하고 있어 연결 검사에서 실패합니다.

### 직접 바꿔 보기

`src/04-integrity-example.js`에서 `chain[1]` 대신 `chain[2]`의 거래를 바꿔 보세요. 해시를 다시 만들지 않은 경우와 다시 만든 경우 모두 `false`인지 확인하세요.

## 지금: 5단계 — 작업 증명(채굴)하기

### 배울 개념

해시는 예측할 수 없기 때문에, 원하는 모양의 해시를 만들려면 입력을 계속 바꿔 보아야 합니다. 이 예제에서는 `nonce`라는 숫자를 `0`, `1`, `2`처럼 하나씩 올립니다.

```text
거래 데이터 + 이전 해시 + nonce 0 → 9a3f...  (실패)
거래 데이터 + 이전 해시 + nonce 1 → bd72...  (실패)
...
거래 데이터 + 이전 해시 + nonce 428 → 000e... (성공)
```

난이도 `3`은 해시가 `000`으로 시작해야 한다는 학습용 규칙입니다. `0`이 많아질수록 성공할 nonce를 찾는 데 평균적으로 더 많은 시도가 필요합니다.

### 실습 순서

1. `src/02-block.js`에서 `nonce`와 `mineBlock()`을 읽습니다.
2. 아래 명령을 실행합니다.

```bash
npm run example:proof-of-work
```

3. 채굴 전과 후의 `nonce`, `hash`를 비교합니다. 채굴 후 해시는 `000`으로 시작합니다.

### 직접 바꿔 보기

`src/05-proof-of-work-example.js`의 난이도를 바꿔 실행하세요.

```js
const difficulty = 4;
```

난이도를 높일수록 일반적으로 더 큰 `nonce`를 찾게 됩니다. 학습용이므로 `5` 이상으로는 올리지 마세요. 실행 시간이 눈에 띄게 길어질 수 있습니다.

## 지금: 6단계 — 거래와 지갑 서명

### 배울 개념

지갑은 코인을 보관하는 통장이 아니라, 거래에 서명하기 위한 **개인키**를 관리하는 도구입니다. 지갑은 한 쌍의 키를 가집니다.

| 키 | 역할 | 공개 가능 여부 |
| --- | --- | --- |
| 개인키 | 거래에 서명. "내가 이 거래를 승인했다"고 증명 | 절대 공개하면 안 됨 |
| 공개키 | 서명이 진짜인지 누구나 검증 | 공개 가능 |

거래를 만든 뒤 금액·보낸 사람·받는 사람 중 하나라도 바꾸면 서명이 더는 맞지 않습니다.

```text
거래 내용 + 민지의 개인키 → 서명
거래 내용 + 민지의 공개키 + 서명 → 유효한 거래인지 검증
```

### 실습 순서

1. 아래 명령을 실행합니다.

```bash
npm run example:transaction
```

2. 첫 결과는 `true`, 금액을 `100`으로 바꾼 두 번째 결과는 `false`인지 확인합니다.
3. `src/06-transaction.js`에서 `signTransaction()`과 `isValidTransaction()`을 읽습니다.

### 중요한 구분

- 해시는 “데이터가 바뀌었는지” 확인하는 지문입니다.
- 전자서명은 “이 거래를 보낸 사람이 정말 개인키 보유자인지” 확인하는 증명입니다.

이 예제에서는 이해를 위해 공개키를 거래의 `sender`, `recipient` 값으로 직접 사용합니다. 실제 블록체인 주소는 대개 공개키에서 파생한 더 짧은 식별자이며, 개인키를 코드·채팅·Git 저장소에 절대 넣으면 안 됩니다.
